# 可重复的 M5 评价协议

## 0. 不得混淆的指标

- `WRMSSE`：12 层级跨序列的加权尺度化点预测误差。
- `WSPL`：不同分位点的加权尺度化 Pinball Loss。
- `Calibration`：分位数的经验覆盖程度。
- `Inventory loss`：给定需求/销售模型、库存政策、成本结构的经济损失。
- `Actual business impact`：必须有现实可执行策略及可信因果对照；竞赛本身不能证明。

## 1. 任务冻结

- 数据来源：官方 M5 Kaggle；记录下载日期、竞赛版本、数据文件 SHA-256。
- 冻结时间边界及外生变量可见性；所有 lag/rolling 特征只能读取预测时间以前的销售事实。
- 明确预测粒度（底层、各聚合层）、预测跨度（28 天）、分位点。
- 在完整官方数据与授权使用边界内复现；不上传原始数据或非许可分发第三方预测。

## 2. 精度复现

- 汇总矩阵须复算出 42,840 条序列和 12 层序列数。
- RMSSE scale 必须按官方规则，从首个非零观测后的 active history 计算；不得随意换历史窗口或分母。
- 对每条序列记录 first_nonzero_index、active_history_length、scale、weight 和状态。
- **零尺度处理纪律**：全零历史、仅一个 active observation、active history 恒定（scale=0）必须显式触发 undefined-scale 状态。禁止加 epsilon、强制设为 0 或静默删除。
- 本轮检查的 companion `Estimate WRMSSE.R` 通过 first non-zero 截取 active history，但计算 `mean(diff(insample)^2)` 时没有显式零尺度 fallback。官方 Accuracy 论文指出 RMSSE 在 naive scale 为零时可能 undefined/infinite。论文报告的 883 条 zero-weight series（因最近 28 天销售金额为零）**不等于** 883 条 zero-scale series；权重为零与 RMSSE 分母为零是不同问题。若正式数据触发 zero scale，先标记 `SCORER_NOT_VERIFIED`，提交逐序列诊断并核实官方评测路径，不自行编造官方约定。
- 权重须按官方金额与层级规则构造，归一化检查；每层权重和、12 层得分和最终平均均单独保存。
- 对计数、空值、零销量、价格缺失分别做检查；禁止静默丢弃记录。
- 输出每层与整体的分数；每条序列报告有效样本与状态。

## 3. 概率复现

- 分位点严格为官方九点。
- 同时输出总体 WSPL、分位点分数、不同层级分数。
- 评估校准与锐度，并显式显示右尾（例如 0.975 和 0.995）的样本不足限制。
- 若模型产生联合路径，检查其跨时间、跨店依赖；没有联合路径的模型不得宣称已识别联合需求风险。

## 4. 多窗口稳健性

采用多个前向滚动的训练/验证窗口，限制全部模型使用相同的信息集；报告：

- 平均/中位分数及跨窗口波动；\n- 每个窗口的 Level 1–12 WRMSSE 与活跃度分组误差；
- 方法排名反转次数；
- 类别、门店、需求类型的分组结果；
- 是否存在极少数大额序列主导平均分数；
- 不允许用最终测试窗口调分位数或融合权重。

## 5. 库存决策评价

- 固定一个（或预注册若干）库存政策，不允许各预测器单独优化成本假设；
- 显式区分 holding、lost-sales、order、review-period、lead-time；
- 输出均值成本、尾部成本、服务率，并跨成本比率敏感性分析；
- 使用历史销量作为需求代理时，必须写出供给截断的限制；
- 所有结果标记 **SIMULATED**，除非有前瞻性实测证据。
